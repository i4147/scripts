    python <merged script filename> <subcommand-or-flags> [options]
## Requirements
1. Use `argparse` for the CLI. Expose every behavior that differs between
   the original scripts as a CLI argument.
   - Prefer **subcommands** if the scripts are distinct "modes"/jobs.
   - Prefer **flags** if they're just variations of one pipeline.
2. Factor out shared logic (imports, helpers, config, error handling) into
   common functions — do NOT duplicate code.
3. Every original script's behavior must remain reachable. Add a mapping
   (in comments or module docstring) like:
       original name1.py  ->  python merged.py mode-a ...
       original name2.py  ->  python merged.py mode-b --flag ...
4. Move hardcoded values (paths, constants, magic numbers) into CLI args,
   with defaults equal to the original values.
5. If the scripts differ in logic that genuinely cannot be unified, keep
   BOTH behaviors behind a flag/choice — never silently pick one.
6. Sensible defaults so it works out of the box; print help if ambiguous.
7. Add type hints, docstrings, and a module-level docstring with usage
   examples.
8. Standard library only, unless the originals already use third-party
   packages — in that case list them explicitly at the top.
## Process
Step 1: Give me a short comparison table — what each script does, what is
        shared, what differs, and your proposed CLI design.
Step 2: Output the full merged script in one code block.
Step 3: Show the exact command for each original script's equivalent.
If anything is ambiguous, state your assumption and proceed. Only ask me a
question if a wrong assumption would silently change behavior. at the end return fully annotated code
